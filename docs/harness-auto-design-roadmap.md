# 자동 Harness — 전체 흐름과 남은 연결

프레젠테이션의 "권장 통합 순서"를 코드로 옮기기 위한 지도. 각 단계가 무엇을
막고 있고 무엇이 열리는지, 그리고 왜 그 순서인지를 적는다.

## 지금 어디까지 왔나

```
사용자 원문
  → RequirementSpec      ✔ 출처·극성·우선순위 검증까지
  → ScenarioBlueprint    ✔ 규칙 기반, 설계 규칙 자체도 감사
  → Coverage Audit       ✔ 11+8 finding
  → Coverage Closure     ✔ 5종 자동 보완, 5종 사용자 확인
  → Preview              ✔ 실행 없이 보여주기
  → EvalScenario         ✘ 여기서 끊긴다
  → 실제 실행             ✘
```

검증 장치는 믿을 만해졌다. 변이 20종 중 19종 탐지, 파일·명령·네트워크 0,
비밀정보 노출 0. **요구사항 이해 정확성은 아직 아니다** — offline 경로는 평범한
기능 요청에서 요구사항을 0개 만들고, 모델 제안은 16개 중 5개만 성립했다.

이 둘을 같은 말로 표현하지 않는 것이 이 문서의 첫 번째 목적이다.

```
전체 테스트 통과   ≠   제품 정확성
```

## 순서와 이유

### 1. 실패 원인 분리

지금은 "모델 제안이 성립하지 않았다"가 한 덩어리다. 그 안에는 네 가지가 섞여
있고 각각 고치는 곳이 다르다.

```
no_response         모델이 아무것도 내놓지 않음        → 프롬프트
malformed           JSON 이 아니거나 형태가 다름        → 프롬프트 · 모델
span_rejected       좌표가 원문과 맞지 않음            → 프롬프트 · 모델
semantics_rejected  인용과 뜻이 반대                   → 모델
accepted            통과
```

분리하지 않으면 2번(모델 선택)도 3번(offline 보강)도 어디를 고쳐야 하는지 모른
채 손대게 된다. 그래서 첫 번째다.

### 2. 모델 선택을 회수율 기준으로

현재는 목록의 첫 eligible을 쓴다. `ax-3.1`이고, 지난 sweep에서
`requirementRecall` 0.447로 가장 낮았다. 임의 선택이 아니라 근거 있는 선택으로
바꾼다.

근거는 격리된 평가 데이터셋이다. **production routing에는 쓰지 않는다** — 그
격리는 유효하다. 여기서 쓰는 것은 "요구사항 후보를 물어볼 모델 하나 고르기"이고,
그 선택이 틀려도 런타임 검증은 그대로 동작한다.

### 3. offline 최소 추출

핵심 목표와 정면으로 부딪히는 지점이다. "로그인 오류를 수정하고 테스트해줘"는
금지도 없고 URL도 없어서 현재 경로가 아무것도 만들지 못한다.

넓히되 발명하지 않는다. 추출은 **동사 + 목적어가 원문에 있을 때만** 하고, 없으면
계속 0개다. 확신은 `ambiguous`에서 시작한다 — 런타임이 읽었다는 것과 그것이 맞다는
것은 다르고, 금지·출처와 달리 여기서는 후자를 보증할 수 없다.

### 4. 실사용 문장으로 측정

15개 fixture는 진단 자료이지 품질 근거가 아니다. 1~3을 하고 나면 무엇이 나아졌는지
같은 잣대로 재야 한다. 지표는 이미 있다.

### 5. Blueprint → EvalScenario, Shadow

변환은 만들되 **실행하지 않는다**. 만들어진 `EvalScenario`가 기존 evaluator가 받는
형태와 맞는지, oracle이 실제 판정 가능한 형태인지를 먼저 확인한다.

여기까지가 이번 범위다.

### 6. 실제 실행과 Arena — 게이트 뒤

정확성 기준을 통과한 뒤에만. 기준은 4번의 측정으로 정한다.

## 무엇이 무엇을 막고 있나

```
1 ──┬──> 2   무엇을 고쳐야 할지 모른 채 모델을 바꾸면 원인이 섞인다
    └──> 3   offline 을 어디까지 넓혀야 하는지 1 이 알려준다
2,3 ───> 4   측정할 대상이 있어야 측정이 의미가 있다
4 ─────> 5   변환은 정확성이 아니라 형태의 문제라 병렬 가능하지만,
             기준 미달 상태로 변환하면 잘못된 계획을 실행 가능한 형태로 만든다
4 ─────> 6   사용자가 건 게이트
```

## 이번 범위에서 하지 않는 것

- 실제 도구 실행, 파일 수정, 명령 실행
- Arena 전략 선택
- Harness Planner (실행 순서·비용)
- VS Code Webview 통합
- 장시간 sweep
- remote push
